# Карта планировщика: ваниль против VARKA (21.10.2026)

Вопрос юзера: из каких частей состоит ванильный «мозг» сталкера, что из этого уже наше, можно ли всё
заменить — то есть посадить игру на наши рельсы, не вырывая ваниль с корнем.

Источники: исходники движка `ANOMALY_DEV/tools/engine_src/src/xrGame` (stalker_*_planner.cpp,
ai_stalker_fire.cpp, object_handler_planner.cpp), скрипты `tools/_unpacked/scripts` (xr_motivator,
modules, state_mgr, axr_*, xr_*), наши `gamedata/scripts/varka_*.script`.

Любую часть мозга удобно спрашивать тремя вопросами: **кто решает** (выбор действия), **кто исполняет**
(ноги, глаза, руки, анимации) и **кто помнит** (что боец знает о мире).

## 1. Ваниль: семь слоёв сверху вниз

| Слой | Что это | Где живёт | Чем владеет |
|---|---|---|---|
| **L0 Стратегия** | куда идёт отряд, какие смарты держит | скрипты: `sim_board`, `sim_squad_scripted`, `smart_terrain` | цель отряда, онлайн/офлайн |
| **L1 Отряд в бою** | общая «доска» отряда | движок: `agent_manager` (member, corpse, enemy, location, explosive) + скрипт `db.used_level_vertex_ids` | кто по кому стреляет, кто где стоит, чей труп |
| **L2 Восприятие/память** | что боец видит/слышит/помнит | движок: `memory_manager` (visual, sound, hit, item, danger, enemy selection); хуки: `visual_memory_manager.script`, `xr_combat_ignore` | лучший враг (`best_enemy`), лучшая опасность, LKP |
| **L3 Главный планировщик** | коммутатор: какое большое дело сейчас | движок `CStalkerPlanner` + скрипты добавляют свои действия | один id текущего дела |
| **L4 Подпланировщики** | как именно делать большое дело | движок: combat, danger, anomaly, alife, death; вложенные | тактика внутри боя/опасности |
| **L5 Исполнители** | тело | движок: movement, sight, object handler (свой GOAP оружия), sound, animation; скрипт: `state_mgr` | путь, поза, взгляд, ствол, реплики |
| **L6 Смерть/ранение** | выход из игры | движок death planner + скрипты wounded | — |

### L3 — главный планировщик (motivation_action_manager)

Движок кладёт шесть операторов: `death_planner`, `alife_planner` (88), **`combat_planner` (89)**,
**`danger_planner` (91)**, `anomaly_planner`, `gather_items`. Цель планировщика одна —
«головоломка решена», и путь к ней всегда идёт через «врага нет» → «опасности нет» → alife.

Скрипты Anomaly добавляют сюда же **свои действия** — так ваниль сама «сажает» поведение поверх движка:

| id | Действие | Чей | Как перебивает бой |
|---|---|---|---|
| 188111 | `axr_beh` (поведение компаньона) | Alundaio | своё свойство |
| 188112 | `xrs_kill_wounded` (добивание) | Anomaly | бой получает условие «добивать не надо» |
| 188113 | `xr_danger` (опасность) | Anomaly (у нас override) | |
| 188115 | `axr_stalker_panic` (паника) | Alundaio | |
| **188118** | **`axr_fight_from_cover` — бой из укрытия** | Alundaio | **полная замена тактики боя скриптом** |
| 18803 | `rx_ff` (не стрелять по своим) | | |
| 18815/16 | `xrs_facer` (рукопашная) | | |
| — | state_mgr +1/+2, схемы logic: walker, remark, sleeper, animpoint, camper, patrol, cover, smartcover, meet, companion, wounded, help_wounded, corpse_detection, gather_items, abuse, combat_camper/zombied/monolith, reach_task (alife) | GSC/Anomaly | |

Важно: **`axr_fight_from_cover` (188118) — готовое доказательство, что замена боевой тактики скриптом
работает.** Это главное действие с условиями «жив, нет опасности, включено», а боевой планировщик и
прочие получают условие «fight_from_cover выключен». Внутри: найти укрытие у врага
(`utils_obj.find_close_cover`), занять ноду (`db.used_level_vertex_ids`), стоять/сидеть по высоте
укрытия (`level.high_cover_in_direction` < 0.2 → присесть), позы `state_mgr` (`sneak_fire`,
`assault_fire`, `threat_fire`, `hide_sniper_fire`), держать точку 3–8 с, потом сменить; нет укрытия —
стрейф вбок на 1–4 м. Шаблон для нашего рельса боя.

### L5 — исполнители (то, чем командуют все слои выше)

- **movement** — тип пути (level/game/patrol), цель (`set_dest_level_vertex_id`), detail path,
  поза тела (stand/crouch), ментальное (free/danger/panic), тип движения (walk/run/stand).
- **sight** — тип взгляда (direction, fire_point, cover, path…).
- **object handler** — свой маленький GOAP оружия: `idle, strap, aim1/aim2, fire1/fire2, reload,
  switch1/2, drop, show/hide…` (в Lua — `object.*`, команда `npc:set_item(object.X, предмет)`).
  `object.reload` есть — тактическая перезарядка по команде возможна (не проверено).
- **state_mgr** (скрипт) — «словарь поз»: 126 состояний в `state_lib` (сочетание тела, движения,
  оружия, анимации и взгляда: `hide_fire`, `sneak_run`, `assault_fire`, `threat_sniper_fire`…), под
  ним свой GOAP `state_mgr_goap`. Ваниль и Alundaio командуют телом через него.
- **sound** (реплики), **animation**.

## 3. Сравнение: что можно заменить полностью

| Часть ванили | Наше сейчас | Заменяемость | Комментарий |
|---|---|---|---|
| L0 стратегия ALife | — | можно, но не сейчас | идея «политика Зоны»; отдельный большой проект |
| L1 доска отряда (agent_manager) | director + lots + intel | **частично уже**; распределение целей — нет | движок сам раздаёт «кто по кому» и укрытия; наши пьесы это не учитывают |
| L2 восприятие C++ | override видимости, belief | **не заменять** | лучи, освещённость, звук — только движок; мы правим формулы и «что из этого следует» |
| L2 выбор врага | — | частично | `best_enemy` движка; влиять можно через `xr_combat_ignore` / свои приоритеты |
| L3 коммутатор | наши действия в нём | **не заменять, использовать** | это розетка: всё наше втыкается сюда |
| L4 combat (тактика боя) | пьесы через hard-приказы; поиск под 34 | **полностью заменяем** (доказано 188118) | но тогда наше должно уметь всё, что ваниль делает молча: граната, добивание, критическое ранение, нет патронов |
| L4 danger | override xr_danger | частично | гранаты оставить ванили |
| L4 anomaly, death, alife-задачи | — | не нужно | |
| L5 movement / sight / animation | командуем | **не заменять** | путь, анимации — только движок |
| L5 object handler (оружие) | выбор ствола | командовать можно (`set_item`) | перезарядка/прицел/огонь по нашей команде — да; сам механизм — движок |
| L5 state_mgr (позы) | почти не используем (сырые `set_*`) | **использовать** | 126 готовых поз с огнём — то, на чём делаются «микромоменты» |

**Вывод.** Полная заменяемость — у **решений** (L1, L3-действия, L4-тактика). У **исполнителей**
(L2-восприятие, L5) — нет и не нужно: это «тело», ему мы командуем. «Рельсы» = наши решения сверху
+ ванильное тело снизу + ванильный коммутатор посередине.

## 4. Правила посадки на рельсы (выучены на крашах и полигоне)

1. **Своё — только в главный планировщик**, как `axr_fight_from_cover`, `xrs_kill_wounded`, наши
   `varka_cmd`/`varka_regroup`. Действие + своё свойство; кто должен уступать — получает условие
   «наше свойство = false» (только те id, что есть у сталкера всегда: `manager:action(id)` ищет
   через `lower_bound` и на чужом id вернёт соседа).
2. **Внутрь C++-подпланировщиков — никогда свои id** (краш `can_cry_enemy_is_wounded`). Подмена
   ванильного id — только там, где так делает сама ваниль (34 = `post_combat_idle.script`), и не в
   кадр, когда это действие идёт.
3. **Исполнители не заменяем — командуем ими.** Поза/огонь — через `state_mgr` или `set_item`.
4. **Каждый наш блок уступает:** раненый (`sidor_wounded`), граната (`danger_grenade`), добивание,
   жёсткий приказ игрока. Список уступок — тот же, что у боевого планировщика (см. как
   `axr_fight_from_cover` перечисляет `rx_ff`, `facer`, `wounded_exist`…).
5. **Один владелец у каждого ресурса.** Сейчас две брони нод (`varka_lots` и
   `db.used_level_vertex_ids`) — свести к одной (наша пишет и в ванильную таблицу).
6. **Выключатель.** Пресет `off` = чистая ваниль. Любой рельс включается только активным пресетом —
   так всегда есть с чем сравнить (матчи: A наш против B ванили).

## 5. Направление (пока «покатать», без вырывания)

1. **Рельс боя** — одно главное действие `varka_combat` по шаблону 188118 и диспетчер режимов, как
   в поиске v0.23. Включено только при активном пресете; при `off` бой ведёт ваниль. Первые режимы —
   уже существующие пьесы ФРОНТ / ПЕРЕКАТЫ / ОТХОД (сейчас они идут через hard-приказ — по сути это
   и есть прототип рельса).
2. **Микрослой бойца** (то, что знают «аркадные челы») — режимы внутри рельса, на позах `state_mgr`:
   - перезарядка в укрытии: магазин < ~30 %, врага не видно → присесть за укрытием, `object.reload`;
   - выход из укрытия с наведённым стволом: взгляд на ожидаемую точку (LKP/belief) **до** шага наружу,
     поза `aim`, огонь — когда увидел;
   - не выглядывать дважды из одного места: после N выстрелов — сменить точку (как 3–8 с у 188118);
   - стрельба с колена, если высокое укрытие держит (`high_cover_in_direction` — помнить, что это
     **открытость**, а не укрытие).
3. **Оружие цельно**: класс, дистанция, мощность, патроны, знание о стволе врага → **роль бойца в
   пьесе** (дробовик идёт вторым номером при штурме, снайпер — на высоте). Выбор ствола становится
   частью решения дирижёра, а не отдельным хуком (сейчас v0.2 — только заплатка поломки 21.10).
4. **Кто по кому стреляет** — распределение целей отрядом (сейчас — движок `agent_manager`).
5. **Паника ↔ мораль** — `axr_stalker_panic` (188115) живёт отдельно от нашей морали; свести:
   паника = следствие морали `broken`.
6. **Хозяин остатков** (идея юзера 21.10, бой «учёный против трёх монолитовцев»). Отряд поредел,
   контакта нет — дирижёр думает как игрок: (1) обойти трупы своих/чужих рядом и взять лучший
   ствол и патроны; (2) выбрать позицию по запечённому зрению — закрытая нода с обзором на подходы;
   (3) **ждать**, а не идти: у кого цель (точка, задание), тот и придёт. Кто должен двигаться, решает
   **мотивация** — в матче это точка (счёт за контроль), в игре — политика Зоны (идея ВКР): без
   цели обе стороны сидят, и это честно.
7. **Позиционка как в матче 3** (21.10, военные-ветераны на ФРОНТЕ против Монолита 1:5): цепь из 4
   через ~5 м, рывки по 7–25 м на контакте, внутри рывка ваниль сама укрывалась (20 % времени),
   уходила от гранат (14 %) и кидала свои (4 %); Монолит без пьесы 31 % времени просто реагировал на
   опасность. Это не совпадение: пьеса + ранг (ветераны против опытных). Проверять — в чистых
   матчах (см. «посторонние» в score.py).

8. **ОКОПАТЬСЯ** (юзер 21.10, после боя Долг против ренегатов: обрез на 90 м, позиционка без мысли).
   Риторика: «вон враги; вон хорошие укрытия, из которых хорошо стрелять; враг далеко — рискнём,
   спринтом туда; там попрячемся по укрытиям и будем поливать». Не всегда и не везде — пьеса в
   арсенале. Кирпичи уже есть: линия огневых точек (`line_slots` во ФРОНТЕ), «держись здесь» +
   ванильное микро (`cover`), запечённое зрение (замкнутость/обзор нод). Не хватает: **выбора места**
   — перебрать кандидатов-линии в радиусе ~40 м (не ближе к врагу, чем сейчас, если враг сильнее),
   счёт = сколько огневых точек «стоя вижу / сидя спрятан» + обзор на подходы − длина перебежки под
   огнём; и **решения «успеем ли»** — враг дальше ~60 м и не стреляет по нам → спринт без огня.
   Дробовикам/обрезам в линии — фланг или «не стрелять дальше 30 м» (сейчас fight_from_cover палит
   из обреза на 90 м).

## 6. Препарат: `axr_fight_from_cover` (Alundaio, 188118)

Файл `tools/_unpacked/scripts/axr_fight_from_cover.script`, 384 строки. Общая схема (generic) —
**стоит у каждого сталкера** (`modules.script`: `LoadScheme(..., stype_stalker)`), но спит.

**Включатель** — переменная бойца `fight_from_point` (vid). Ваниль ставит её только компаньонам по
команде «жди здесь» (`axr_companions.set_companion_to_wait_state`). Мы — в пьесе `cover`
(`varka_plays` v0.2): точка = где боец стоял при контакте.

**Оценщик** (`evaluator_fight_from_cover`) — «да», если: жив; не ранен; не кемпер; не «не стреляй»
(`rx_dont_shoot`); не помогает раненому; нет гранаты рядом; точка задана; лучший враг жив и не ранен.

**Проводка** (образец для нашего рельса):
- условия действия: жив, `danger = false`, своё свойство = true, не ранен (`sidor_wounded_base`,
  `wounded_exist`), не занят `rx_ff` (свои на линии огня), `gl` (перезарядка подствольника), `facer`
  (рукопашная);
- уступают ему (получают «fight_from_cover = false»): `xr_danger`, **боевой планировщик**, планировщик
  опасности, state_mgr+2, alife. То есть, пока он включён, ванильного боя нет вообще.

**Цикл каждого апдейта:**
1. Путь — по уровню. Куда смотреть: видит врага → шея врага; не видит → **последняя известная точка**
   (`memory_position`) — ствол заранее наведён туда, откуда враг появится.
2. Есть своя нода укрытия:
   - раз в 5 с — стоять или сидеть: `level.high_cover_in_direction(нода, на врага)` < 0.2 → сидеть,
     ≥ 0.2 → стоять (функция отдаёт **открытость**, см. наши заметки — логику стоит перепроверить);
   - на ноде: поза `state_mgr` — снайпер `threat_sniper_fire`/`hide_sniper_fire`, иначе стоя
     `threat_fire`, сидя `sneak_fire`; без цели — `threat`/`sneak_run`;
   - **держит ноду 3–8 с (случайно), потом отпускает** → следующий апдейт ищет новую: не высовываться
     дважды из одного места;
   - в пути к ноде: ближе 20 м к врагу — стреляет на ходу (`assault_fire` / `sneak_fire`), дальше —
     просто бежит.
3. Ноды нет → `try_go_cover`: движковый `npc:best_cover` вокруг точки (1→10 м, если точка задана;
   иначе 5→20), нода не занята другим (`db.used_level_vertex_ids`) → занять. Не нашлось →
   `try_to_strafe`: шаг вбок ±90° на 1–4 м. (`try_go_backward` — назад на 8 м — написан, не вызывается.)
4. Выход — отпустить ноду.

**Чего в нём нет:** командной работы (каждый сам), перезарядки по уму (её делает движок где попало),
гранат (при гранате выключается), выбора ствола, морали, отхода. Это и есть то, что добавляет наш
дирижёр сверху: точку и момент даём мы, микро — он.

**Попутный вывод:** движковый `best_cover` ни при чём в крашах 20.10 (виноваты были наши id) — его
можно снова использовать, ваниль зовёт его повсюду.
