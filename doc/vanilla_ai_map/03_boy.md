# 03 — Что творится В БОЮ

`property_enemy = true`, планнер отдал руль combat. Дальше — либо C++-движок (по
умолчанию), либо одна из трёх Lua-схем. Разберём все четыре. Все — **на одном NPC,
без оглядки на соседей.**

---

## Общий боевой цикл (справедлив для всех типов)

```
        ┌───────────────────────────────────────────────┐
        │              ВИЖУ врага (see == true)          │
        │   set_sight(fire_point, враг) · огонь fire1    │◄────┐
        └───────────────────────┬───────────────────────┘     │
                                │ потерял LOS                  │ снова увидел
                                ▼                              │
        ┌───────────────────────────────────────────────┐     │
        │        НЕ вижу, но бит ещё жив (LKP)           │     │
        │   стреляю/смотрю в memory_position (призрак)   │─────┘
        └───────────────────────┬───────────────────────┘
                                │ memory_time истёк
                                ▼
        ┌───────────────────────────────────────────────┐
        │   ВРАГ ЗАБЫТ → property_enemy = false          │
        │   combat отваливается → post_combat_wait       │
        │   озираюсь N сек → возвращаюсь на job          │
        └───────────────────────────────────────────────┘
```

Различие между типами — **только в среднем блоке**: держать точку? бежать на LKP? как
именно стрелять? Всё остальное одинаково.

---

## Тип 1 — ⚠️ C++-БОЙ (default: наёмники, Долг, бандиты)

Внутренности в бинарнике, из Lua не видны. По наблюдению и SDK — примерно так:

```
   1. get_item_to_kill   достать/поднять оружие под дистанцию
   2. рядом есть smart_cover, прикрывающий от memory_position?
        ДА  → занять loophole (амбразуру) укрытия, стрелять из-за него
        НЕТ → стрелять с места / с приседа, иногда перебежать к укрытию
   3. kill_enemy         огонь по memory_position (разброс = ранг × оружие × поза)
   4. потерял → держит огонь по LKP, потом post_combat_wait
```

**Умные на вид, тупые по сути детали:**
- Занимает **заранее расставленные** smart_cover-точки (level designer их поставил).
  «Грамотно засел» = дизайн уровня, не решение NPC.
- Угол амбразуры **запечён** и не пересчитывается под твою реальную позицию (§НАБЛ 7.1) —
  отсюда «стреляет в стену рядом с амбразурой».
- Ранг влияет на **разброс пули и скорость реакции**, НЕ на поведение. Новичок и мастер
  делают одно и то же, мастер просто попадает.

## Тип 2 — ✓ camper (держит точку)

Файл `xr_combat_camper.script`, 2 действия:

```
   act_shoot        state_mgr.set_state("hide_fire", look_object = best_enemy)
                    → сидит в укрытии, стреляет пока ВИДИТ
   act_look_around  потерял из виду → крутит головой по last_seen_pos,
                    НО с точки не сходит
```

Это «часовой»: увидел — жжёт из укрытия; потерял — озирается; **никогда не преследует.**
Достать такого = зайти в его сектор, потому что сам он к тебе не пойдёт.

## Тип 3 — ✓ monolith (прёт на LKP)

Файл `xr_combat_monolith.script`, 4 действия + порог дистанции (случайный 20–35 м):

```
   evaluator_close   враг ближе random(20..35)м?
   act_fight_close   близко → бой в упор
   act_fight_far     далеко → бой с дистанции
   act_look_around   потерял из виду → озирается
   act_go_to_pos     идёт на last_seen_vertex (ТУДА, где видел последний раз)
```

Ключевое: monolith **сокращает дистанцию** — топает на твою LKP. В открытом поле это
давит. В коридоре (см. сценарий 3) это самоубийство: идёт по прямой тебе в прицел.

## Тип 4 — ✓ zombied (бредёт на LKP)

Файл `xr_combat_zombied.script`: идёт на last_seen по прямой (`move.line`), стреляет,
**в основном игнорит попадания** (реакция на hit подавлена). Медленный, тупой, живучий
мясной таран. Ноль тактики намеренно — это фича зомби.

## Общая для всех развязка боя: combat_ignore и post_combat

```
   враг потерян
        │
        ▼
   memory_time тикает ~still_visible_time... истёк
        │
        ▼
   combat_ignore   ← движок на ~60с помечает «не лезь снова в бой по этой памяти»
        │
        ▼
   post_combat_wait ← постоял, поозирался вокруг СВОЕЙ точки
        │
        ▼
   alife_planner   ← пошёл обратно на job, будто ничего не было
```

Именно этот хвост мы атакуем: §НАБЛ 7.9 «тревога умирает раньше облака», §НАБЛ 7.14
«alert ≠ belief». Ваниль: поискал-у-своих-ног-и-домой. Мы: облако ведёт ноги, тревога
живёт отдельной осью.

## Словарь тела в бою (чем командует execute)

| Глагол / состояние | Смысл |
|--------------------|-------|
| `set_sight(look.fire_point, pos)` | целься сюда |
| `set_item(object.fire1, wpn)` | огонь |
| `set_state("hide_fire", {look_object=враг})` | сесть в укрытие и жечь |
| `set_body_state(move.crouch)` | присесть |
| `set_movement_type(move.run)` | бежать (перебежка к укрытию) |
| `send_to_nearest_accessible_vertex(vid)` | иди на ноду (monolith go_to_pos) |
| `state "look_around/poisk"` | озираться при потере |

Никакого «перекатиться», «выглянуть с левого плеча», «слайд в укрытие» — таких
**анимаций нет**, значит и действий нет. Словарь тела = потолок поведения (см. слой 3
в основном разборе GOAP-surface).
